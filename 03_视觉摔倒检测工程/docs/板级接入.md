# 板级接入（VF-E20NG88 / EG4S20NG88）

视觉核本身已经在 TD 里综合 + 布局布线跑通，这里记录把它接到板子上的
全部前提：管脚在哪、官方例程缺什么、`gray_front` 对流的要求。

## 0. 当前状态（已实现）

板级顶层 `fpga/rtl/fall_camera_top.v` 已经写完，整条链**全部在 FPGA 内**，
没有 PLL、没有外部帧缓存、没有 MCU/软核：

```
OV5640 --DVP 8bit--> cmos_capture_rgb565 --> fall_core_top --> 74595 LED
   ^                     (等 10 帧)              |                + 115200 串口
   |                                            |
   +---- SCCB 250 条寄存器 ------------ ov5640_sccb_cfg
```

| 文件 | 作用 |
| --- | --- |
| `rtl/cmos_capture_rgb565.v` | DVP 8 bit 字节对 → RGB565；VSYNC 上升沿出 `frame_start`；等 10 帧稳定后 `armed`；`hw_err[3:0]` 报错 |
| `rtl/ov5640_sccb_cfg.v` | 24 MHz → 250 kHz SCCB 主机，250 条寄存器；`0x3008=0x82` 之后插 2 ms 稳定期再写 `0x02` |
| `rtl/led595_shift.v` | 74595 移位驱动 |
| `rtl/status_uart.v` | 115200 8N1，`F<frame> <found> <x> <y> <w> <h> <area> <state>\r\n` |
| `tb/tb_board_top.v` | 行为级 OV5640 + SCCB 从机 + UART/74595 解码，`+LONG` 跑「站立 → 跌倒」 |
| `td/board_pnr.tcl` | 板级完整综合 + 布局布线 |

**LED 映射**（74595，bit0 先出）：

| bit | 含义 |
| --- | --- |
| 0 | `cfg_done`：SCCB 配置完成 |
| 1 | `armed`：采集已经稳定 10 帧 |
| 2 | 1 Hz 心跳 |
| 3 | `bbox_found` |
| 4 | `FALL`（状态机在 FALL） |
| 5 | `alarm` 锁存（约 2 s） |
| 6 | `hw_err`（VSYNC/HREF 异常） |
| 7 | `frames arriving` |

**串口**只发状态行，9600 以上任何串口工具都能看；一行对应一帧，
可以直接在电脑上画包围盒（算法本体仍在 FPGA 内，电脑只负责画）。

## 0.1 两个时钟域

| 域 | 频率 | 内容 |
| --- | --- | --- |
| `cmos_pclk` | 48 MHz | 采集、`fall_core_top` 整条算法链、报警脉冲 |
| `clk_24m` | 24 MHz | 按键去抖 / 上电复位、74595 移位、115200 串口、心跳 |

两者之间只有三个信号，全部走「源域翻转 + 目的域三级同步 + 边沿检测」：

```
cmos_pclk                                   clk_24m
  bbox_valid ─latch s_*─┐                     ┌─ 3FF ─ snap_pulse ─ 快照 u_*
                 snap_tog ──────────────────┘
  alarm ────────── alarm_tog ────────────────┴─ 3FF ─ alarm_pulse ─ 报警锁存 2 s
  armed ─────────────────────────────────────┴─ 3FF ─ armed_24m ─ 状态灯
```

跨域只传翻转标志，多 bit 的 `s_*` 总线在源域锁存后**整整一帧（33 ms）**
保持不变，24 MHz 侧最快也要两个 41.7 ns 周期后才采样，采样时总线早已稳定。

> **为什么报警必须是单拍脉冲**：`alarm_tog` 是报警跨域的唯一载体。如果
> `alarm` 在 48 MHz 域里保持高电平一整帧（33 ms ≈ 160 万个时钟），
> `alarm_tog` 就会以 48 MHz 连续翻转，24 MHz 侧采到的是一个近似随机的
> 方波，报警锁存和 LED 都可能不响应。`tb_alarm_pulse.v` 就是为此加的回归。

## 0.2 posture_fsm 的输入流水与 testbench 驱动约定

板级 P&R 第一版在 48 MHz 下差 0.161 ns 收不回来，最差路径从 bbox 高度
一路穿过 `w*h`（MULT18）、`20*h`/`13*ref_h` 移位加、cy 减法、sunk/ground
比较，最后进 `pending_frame` 的优先编码，一共 16 层逻辑。现在的
`posture_fsm` 在输入口加了一级流水：

```
en=bbox_valid ──┐
                ├─ 第 1 拍：存观测 + w*h + 比例比较（p_* 寄存器）
                └─ 第 2 拍：原状态机在 p_* 上做判决（en_q 选通）
```

判决逻辑和 Python `PostureMachine` 完全一致，只是晚一个时钟出来。对使用
这个模块的人只剩一条约定：

**观测只要在 `en` 那一拍有效**。第 1 拍把它连同乘积、比例比较一起锁进
`p_*`，第 2 拍状态机只读这些寄存器——`p_valid`、`p_frame`、`p_x..p_area`
一个都不少。调用方在 `en` 之后的下一拍就可以去数自己的下一帧。

> 这条约定是踩过坑才收窄的。第一版流水里只有观测数据进了寄存器，顺序块的
> 判断仍然在读输入端口（`frame`、`valid`、`y`...）。`tb_vision_chain.v`
> 恰好是「bbox 脉冲那一拍就把 `fsm_frame` 加一」的写法，于是状态机在第 2 拍
> 看到 `frame+1`：**`pending_frame` 记成 30（应为 29），报警从帧 31 漂到
> 帧 32**。板级顶层（`bbox_*` 整帧稳定）和 `tb_posture_fsm.v`（向量保持
> 两拍）都掩盖了这个 bug，只有整链长程回归暴露了它。现在
> `tb_posture_fsm.v` 带 `+HOSTILE=1`：`en` 一拉低就把 `frame` 加一，专门
> 复现这种调用方式，`rtl_check.py` 默认按这个模式跑。

同源的第二个坑：`posture_fsm.v` 里 `rh/rw/ry/ra` 原本声明在第一个使用者
之后，TD 报 `HDL-5373: identifier 'rh' is used before its declaration`
并另建隐式网。Icarus 不报错，仿真全绿；TD 的网表却多了约 190 个 LUT
（综合后 12,185 → 12,377），默认种子的布线因此从「布通」变成 1 处
`PHY-8023 短接`。把这段声明提到所有使用者之前，警告消失、网表回到正常
大小。**综合器的 warning 不能当噪声过。**

testbench 侧的采样点：`tb_vision_chain.v` 在 bbox 脉冲后的第 2 个边沿读
状态与报警（第 2 拍判决刚生效、`alarm` 还是单拍高电平），第 3 个边沿只能
读到状态、读不到报警脉冲；`tb_posture_fsm.v` 在消费边沿之后 `#1` 取值。
两个 testbench 都会把另一种采样点打在 `DBG<n>` 行上，真出分歧时能一眼
看出是「采样晚了」还是「状态机算错了」。

## 1. 器件与管脚预算

- 器件：EG4S20NG88，**合封 SDRAM**（原理图标注「EG4S20NG88合封SDRAM」）。
  SDRAM 走封装内部连接，**不占用户管脚**，所以官方例程的 `.adc` 只约束
  了 22 个管脚。
- 用户可用 pad：**66** 个。核心诊断顶层 `fall_core_top` 引出 79 个，
  TD 直接报 `PHY-9016 ERROR: Design's pad number = 79, exceeds the limit
  66`。做 P&R 时用 `td/fall_core_pnr_top.v` 把 bbox 输出折成 8 位签名，
  板级包装则把 bbox 直接接到片内 HDMI 叠加逻辑，不引到 pad。

## 2. 相机接口（J4，10x2 排母）

原理图网名 ↔ 官方 `.adc` 网名 ↔ 管脚（位置取自
`06_Anlogic_Examples/03-3_CMOS_MT9V034_Gray_752480/sdc/EGS20NG88_Board.adc`，
与 03-4 OV5640 例程一致）：

| 连接器网名 | 官方网名 | 管脚 | 方向 |
| --- | --- | --- | --- |
| Sensor_D0 … Sensor_D7 | cmos_data[0..7] | P2, P87, P86, P78, P77, P76, P75, P74 | in |
| Sensor_PCLK | cmos_pclk | P79 | in |
| Sensor_HREF | cmos_href | P62 | in |
| Sensor_VSYNC | cmos_vsync | P66 | in |
| Sensor_XCLK | cmos_xclk | P72 | out |
| Sensor_SCLK | cmos_sclk | P70 | out (SCCB) |
| Sensor_SDAT | cmos_sdat | P71 | inout (SCCB) |
| Sensor_CTL0…3 | — | — | 备用控制（复位/掉电等） |

相机接口共占 14 个 pad。其余已确认的板级管脚：

| 功能 | 管脚 | 备注 |
| --- | --- | --- |
| clk_24m | P13 | 板载 24 MHz 晶振 |
| HDMI_CLK_P / D0_P / D1_P / D2_P | P47 / P49 / P55 / P61 | LVDS25，N 端由 TD 自动配对 |
| led595_clk / latch / dout | P59 / P57 / P45 | 74595 移位 LED |

22 个 pad 与官方 `.adc` 的 22 条约束一一对应，剩下的预算留给报警
（LED/蜂鸣器/串口）和 E104 小板联动。

## 3. 官方例程缺什么

`06_Anlogic_Examples/03-4_CMOS_OV5640_Color_1280720` 的 `.al` 工程里
`<Source_Files>` 引用了这些文件，**随包发布的目录里只有 3 个 .v**：

| 引用文件 | 是否随包发布 | 处理办法 |
| --- | --- | --- |
| `src/CMOS_Capture_RGB565.v` | 否 | **已自写** `rtl/cmos_capture_rgb565.v`（见下节契约） |
| `src/I2C_OV5640_Init_RGB565.v` | 否 | **已自写** `rtl/ov5640_sccb_cfg.v`，250 条寄存器表 |
| `src/Sdram_Control_2Port_512Kx4x32Bit/*` | 否 | **不需要**：算法全片内，不引外部帧缓存 |
| `src/lcd_24bit_ip/*` | 否 | HDMI 叠加时才需要，可先用官方 01-1 HDMI TX 例程 |
| `src/system_index/system_ctrl_pll.v` | 否 | **不需要**：全设计跑 `cmos_pclk`，不生成 PLL |

相机侧不需要 PLL 是个关键决定：`cmos_pclk` 就是 OV5640 的像素时钟
（本配置 48 MHz，见 `fall_camera_top.sdc`），捕获、算法、串口输出全在
这一个域里，因此没有任何跨时钟域要处理，ERAM/DSP 也省下来给算法用。

03-1/03-2/03-3 的 `sim/` 目录里都有完整的 I2C 时序控制器
`i2c_timing_ctrl_reg16_dat16.v`（22 KB，寄存器表驱动的 16 位地址/数据
控制器），03-4 缺的 `I2C_OV5640_Init_RGB565` 就是「控制器 + OV5640
寄存器表」，寄存器表本身是公开的标准序列。

## 4. 采集模块要满足的契约

`gray_front` 只认三件事（其余内部自己数）：

1. `de_in`：每个有效像素一个时钟，**640x480、RGB565、行序从上到下**；
2. `pix_in[15:0] = {R[4:0], G[5:0], B[4:0]}`，大端按官方例程的
   `cmos_data` 拼法（D[7:0] 连续两个字节，先高后低）；
3. `frame_start`：每帧**一个时钟脉冲**，必须落在垂直消隐里，且只被一个
   posedge 看到（`de_in=0` 期间拉高、下一个 negedge 拉低）。

另外两条已经在 `fpga/README.md` 里写死的约定，采集侧必须配合：
`motion_morph` 在帧末要 7 行 flush（7x326 拍），这段时间必须落在消隐
内；`proj_bbox` 输出的是**上一帧**的 bbox，一帧一个 `out_valid` 脉冲。

## 5. 接线顺序建议

1. 先只接相机 + `gray_front`，把 `de_out` 的行数（应为 180）和
   `frame_start` 计数引到 74595 LED 或串口，确认整帧时序；
2. 再接 `frame_diff` / `motion_morph`，用 ILA/片内探针看掩膜行数；
3. 最后接 `proj_bbox` + `posture_fsm`，报警先出到 LED，再接 HDMI 画框。
