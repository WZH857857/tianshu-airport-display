# ADV09 人声播报循环（2026-09-28）

## 需求

上一版 ADV08 的人声播报只播一遍：图片缓存完成后从 TF 卡根目录取
`VOICE.WAV`，播完就交回片内机场提示音，再也不会响第二次。实际展示时
这不够用，航显大厅的广播是周期性播报的。

本版把它改成自动循环：

> 播报结束，等 60 秒，再从这里（文件第一个样本）重新播一遍，如此往复。

重播不需要按键、不需要重新上电，也不受切图影响。

## 实现

新增 `rtl/audio/voice_repeat_ctrl.v`，由一个四级状态机负责"什么时候
再启动一次"：

| 状态 | 含义 | 离开条件 |
| --- | --- | --- |
| `S_FIRST` | 等图片缓存就绪 | `voice_ready` 有效 → 发一个 `start_pulse` |
| `S_ACTIVE` | 播报进行中 | `stream_done` → `S_GAP`；`stream_error` → `S_STOP` |
| `S_GAP` | 60 秒间隔计时 | 计时到 → 再发一个 `start_pulse` |
| `S_STOP` | 出错停机 | 只有复位能回到 `S_FIRST` |

`voice_ready = scan_done && voice_found && player_cache_ready`，和无按键
自动播放的条件完全一致，所以第一遍的启动时机没有改变。

间隔用"秒"计数，不依赖仿真时长：

```verilog
parameter [25:0] GAP_TICK_CYCLES = 26'd50_000_000;  // 50 MHz 下一拍 = 1 s
parameter [7:0]  GAP_SECONDS     = 8'd60;           // 间隔 60 拍
```

两个参数同时暴露到顶层（`VOICE_REPEAT_GAP_TICK_CYCLES` /
`VOICE_REPEAT_GAP_SECONDS`），所以仿真可以把它缩短成十毫秒级的一拍，
跑的是同一段逻辑，板级默认值仍然是严格的一分钟。

`waiting` 输出直接由状态译码（组合逻辑），而不是打一拍：寄存一版会让
"间隔中"这个标志多持续一个时钟，和重播脉冲在同一拍重叠，测量和后续
逻辑都会被带偏。

顶层 `hdmi_mm_player` 侧的配合改动只有三处：

1. 用一个单周期 `voice_start_pulse` 取代原来的"上电只发一次"启动条件，
   送给 `wav_voice_stream.start` 和 FAT 读卡器的 `load_start`；
2. 每次重新启动时，重新翻转 `voice_stream_start_tog`，并清掉
   `voice_stream_done_latch`、`voice_stream_stop_seen` 和 5 秒看门狗计数，
   让音频侧把新的一轮当成一次全新的流；
3. 把 `stream_error` 接到重复控制器，出错即停机。

视频、淡入淡出、缩放、图层、OSD、音频可视化、TF 文件命名都没有改动。

## 间隔期间听到什么

播报结束时，FIFO 里通常还压着最多 1024 个样本（8 kHz 下约 128 ms），
音频侧把这点尾巴放完之后 `voice_generating` 拉低，HDMI 音频岛立刻回到
片内机场提示音（E5 → C5 循环）。所以那 60 秒不是静音，而是"提示音在放，
人声还没开始"——这也正好可以用来确认音频通路一直活着。

## 验证

### 1. 调度状态机

`sim/tb_voice_repeat_ctrl.v` 把一拍缩短成 5 个时钟、间隔缩短成 2 拍，
检查：

- 图片缓存就绪之前不发启动脉冲；
- 启动脉冲只持续一个时钟；
- 第一次 `stream_done` 之后间隔长度正好是 2 x 5 = 10 个系统时钟；
- 连续两轮都能按时重播；
- 出现 `stream_error` 之后不再发启动脉冲。

```text
VOICE REPEAT TB: PASS
```

### 2. 两轮完整链路

`sim/tb_voice_repeat_e2e.v` 把重复控制器、`wav_voice_stream`、
1024 字节异步 FIFO 和 48 kHz 播放器按顶层的接线方式连起来，用
`sim/adv09_short.wav`（444 字节，8 kHz / 16 bit / 单声道，200 个样本）
走真实的字节握手推两遍，间隔缩短为 12 x 10 ms = 120 ms：

```text
round 0 pushed 444 bytes, start cycle 8, done cycle 1097
round 0 drained at cycle 1249999
round 1 pushed 444 bytes, start cycle 6001100, done cycle 6002189
round 1 drained at cycle 7251025
VOICE REPEAT E2E: PASS
rounds: 444 bytes, 444 bytes; gap 6001092 cycles; 2394 audio frames
```

两轮间隔 6 001 092 个 50 MHz 时钟（= 120.02 ms，等于配置的 120 ms 加上
第一轮 1 092 个时钟的解析时间）。第一轮在间隔内把 FIFO 排空并交回提示音，
第二轮从样本 0 重新解析（`samples_out` 回到 200），播放器再次产生音频
（2 394 帧，等于两轮各 200 个样本上变频到 48 kHz 的期望值 2400 附近），
整个过程 `parser_error = 0`。

### 3. 回归

`sim/regress_adv09/` 是本次改动的回归目录，覆盖音频链路
（`tb_hdmi_audio_chain`、`tb_voice_chain_e2e`、`tb_voice_stream_*`、
`tb_ulaw`）、进阶 4 / 进阶 5 的叠加层
（`tb_param_control`、`tb_param_overlay`、`tb_ui_overlay_adv01`、
`tb_audio_vis`）以及转场（`tb_fade_ctrl`、`tb_fade_timing`）；
结果见同目录 `summary.txt`。

`tb_voice_chain_e2e.v` 原来的排空等待固定为 400 000 个音频时钟
（32.5 ms），短于它自己合成的那段 1024 样本 / 8 kHz 音频（128 ms），
所以会误报"提示音没有交回来"。本次把它改成按 `voice_generating` 实际
排空来等待（上限 3 000 000 个音频时钟），并把合成音频缩到 256 个样本
（32 ms）——字节通路、FIFO 回压和提示音交回判定完全相同，但这一条回归
从原来要跑十几分钟变成 20 秒，现在它真正验证了"播完交回提示音"这一条：

```text
parser: done=1 error=0 code=0 samples=256 rate=8000 ch=1 bits=16
audio: frames=1536 non-zero=1534 generating=0
RESULT: PASS tb_voice_chain_e2e
```

## 上板

1. TF 卡根目录放 1 ~ 6 张 `.BMP`（24 位未压缩）和一个 `VOICE.WAV`。
   文件名必须是 ASCII 8.3 短名，中文名不会被扫描到。
2. TD 下载一律用 `PROGRAM_SRAM`，不要用 `PROGRAM_FLASH`
   （本板配置 flash 里是一份旧设计）。
3. 显示器/电视要带喇叭，否则听不到声音不能说明音频链路失败。

预期现象：上电 → 图片缓存完成 → 人声从第 0 秒开始播 → 播完 60 秒提示音
之后从头再播，一直循环；播报过程中按 `KEY1` 切图不会让人声重启或中断。

上板时先量第一遍播完到第二遍开口的时间，确认约为 60 秒（加上 FIFO 里
那不到 0.2 秒的尾巴）。
