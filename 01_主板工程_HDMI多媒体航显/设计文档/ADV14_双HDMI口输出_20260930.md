# ADV14 双 HDMI 口输出（HDMI A + HDMI B 镜像，2026-09-30）

## 1. 这一步做了什么

开发板上有 HDMI A、HDMI B 两个输出口。之前工程只驱动 A 口，B 口的引脚
一直空着。ADV14 把同一路 TMDS 流同时送到两个口，**两个屏幕显示完全一样
的画面**，包括实时航班看板、分辨率 OSD、字幕、音频可视化与 HDMI 音频。

上位机、串口协议、按键、TF 卡、人声播报全部不变，一个新命令都没加。

## 2. 引脚

| 信号 | A 口 | B 口 |
| --- | --- | --- |
| TMDS CLK | K1 | C3 |
| TMDS D0 | F5 | G5 |
| TMDS D1 | E3 | F1 |
| TMDS D2 | B3 | E1 |
| DDC SCL | P1 | P2 |
| DDC SDA | R1 | R2 |

B 口点位与官方例程 `vendor/lab_ex5_i2s/.../pin.adc` 一致。

## 3. 为什么是镜像而不是两套独立画面

顶层在 `rtl/hdmi_adv04_voice.v` 里把 B 口的 6 根输出信号直接连到 A 口：
HDMI 1.4b 发送核与 TMDS 串化器只有一套，被驱动的物理输出引脚有两组。

要做到"两块屏幕显示不同内容"，需要**第二条完整视频通路**：第二个像素时钟
域、第二套 SDRAM 读端口、第二组 TMDS 编码与串化器。当前工程的情况是：

| 资源 | 现值 | 说明 |
| --- | --- | --- |
| slice | **95.48%**（约 9357 / 9800） | 已无空间再放一路像素读出 |
| SDRAM | **1 片**，六帧缓存已被图片播放占满 | 没有第二片给第二路做帧缓存 |
| TMDS | 1 套发送核 + 1 组串化器 | 第二组要再实例化一次 |

也就是说，"两个口都出图"能做，"两个口出不同图"在这块板子的当前余量下
做不了。这不是软件问题，是资源和器件数量问题。

## 4. 可实施的替代方案：轮播多批信息

如果验收需要看到"信息在轮换"，可以在**两个屏幕同步显示**的前提下做时间
分片轮播，观感上等于两块屏互相接力：

| 时间段 | 屏幕内容 | 上位机行为 |
| --- | --- | --- |
| 0–10 s | 第 1 组航班信息 | 两屏相同 |
| 10–20 s | 第 2 组航班信息 | 两屏相同，第 2 组在 FPGA 里实时替换 |
| 20–30 s | 第 3 组航班信息 | 同上，依次轮到第 6 组 |
| … | 一轮播完 | 回到第 1 组，无限循环 |

每批信息都由上位机通过现有 `BOARD`（0x20）命令实时改写，改完立刻上屏，
不用重新烧写、不用换卡。具体做法是**上位机侧轮播**：PC 里保存若干批航班
信息，定时把下一批通过 `BOARD` 命令写进 FPGA，写完立刻生效。这样做的好处
是 FPGA 侧一行 RTL 都不用改——当前字符缓存只有一份、资源余量又只剩 4.5%，
再往里塞第二份缓存会把时序压垮。

上位机已经按这个思路实现了：

| 控件 | 行为 |
| --- | --- |
| 六屏 / 编辑 | 面板默认显示六块小屏，一块对应一张图；切到「编辑」改当前组的 6 行 |
| 信息组下拉框 | 六组，每组 6 行，与 IMG01…IMG06 一一对应 |
| 六块小屏 | 每块显示该图的 6 行；正在播的那块橙框高亮并标「播放中」，随板卡状态实时移动 |
| 跟随切图（默认开） | 画面每换一张，就把该图对应的那组整页重新下发；上位机每秒查一次状态，切图后 1 秒内上屏 |
| 每 10 秒轮换 | 勾选后整组自动循环，第六组播完回到第一组，无限重复 |
| 同步整页 | 手动把当前组立刻下发，不用等轮换 |
| 实时编辑 | 任意一行改完 450 ms 自动下发；小屏同步显示改动；轮换前会把改动存回该组 |

每张图有自己的一组信息：IMG01 早高峰离港、IMG02 午高峰离港、IMG03 进港到达、
IMG04 中转联程、IMG05 延误取消、IMG06 国际航班。切图时上位机把该图的那组 6 行
整页重新下发，两块 HDMI 屏上的看板整组更换；小屏墙上同一时刻只有一块高亮，
代表当前在播的那组。点任意一块小屏会切到「编辑」并载入该组，改完即生效。
关掉「跟随切图」后看板不再随画面联动，只跟下拉框或 10 秒轮换走。

轮换只动信息、不动画面：图片、淡入淡出、人声播报、音频可视化都不受
影响，两个 HDMI 口照常同步显示。

### 4.1 高 DPI 与长页面适配

2026-09-30 23:15 更新的上位机还处理了高分屏和窄窗口：

- 启动时启用 Windows 高 DPI 缩放，系统设为 125% / 150% / 200% 时，
  界面不会再按物理像素显示得又小又挤。
- 左、中、右三列各自带纵向滚动条，鼠标停在任意一列都可以直接上下滑动。
- 六屏墙按中间列宽度自适应：窗口够宽时两列三行，窗口较窄时改为单列六行，
  避免横向裁掉按钮、第三张图片或右侧信息。
- 画面槽位保持三列排布，分辨率继续显示在图片下方；未缓存状态改为缩略图
  上的角标，既醒目又不会把卡片标题撑宽。

## 5. 构建结果

| 指标 | 结果 |
| --- | --- |
| Route Setup WNS | **+181 ps**（S-EP = 0） |
| Route Hold WNS | **+27 ps**（H-EP = 0） |
| 资源 | 约 9357 / 9800 slice（95.48%）、28 BRAM、20 DSP |
| 种子 | seed 1 |
| 位流 | `hdmi_adv13_board.bit`、`adv13_seed1_pass.bit` |

版本号从 `v13` 提到 `v14`，板卡状态栏可以用来确认烧进去的是这一版。

B 口只是把已经算好的 TMDS 输出再驱动一组 LVDS 引脚，逻辑侧没有新增计算，
所以镜像本身几乎不花资源。

## 6. 上板验收

1. 烧 `adv13_seed1_pass.bit`；桌面另存了一份 `hdmi_adv14_ab_board_seed1.bit`。
   下载选 `PROGRAM_SRAM`，时钟 5 MHz。
2. 两个 HDMI 口各接一块屏（或电视）。
3. 两块屏应显示同一画面；上位机点任意一张图、改任意一行看板，两块屏
   同时变化。
4. 音频从两块屏的扬声器都能听到，人声播报、切图不重置照旧。

> 注意：DDC/EDID 只走 A 口。发送核按 A 口屏幕的能力协商分辨率，B 口
> 屏幕按同样的 640×480@59.3 Hz 接收。若 B 口屏幕不支持该模式，需要它
> 自己完成一次缩放；工程侧不额外做检测。
