# ADV10 手动 / 自动切图（2026-09-28）

## 需求

ADV09 及以前，六张图片在缓存完成后就自己按 6 秒轮播，`KEY1` 只是打断它。
展示时希望上电先停住：

> 默认不切图，自动切图用开关。

也就是：上电停在当前这张不动，只有把板上的开关拨上去才进入自动轮播；
手动切图仍然按 `KEY1`。

## 板上分工

| 资源 | 位置 | 作用 |
| --- | --- | --- |
| `SW1` | FPGA 引脚 `C8`，拨上 = 1、拨下 = 0 | 切图模式：拨下 = 手动（上电默认），拨上 = 自动 |
| `KEY1` | `A2`，低有效 | 手动切下一张，自动模式下也能立即切 |

引脚依据《HX4S20开发板手册-HDL版2410.pdf》第 2 章：SW1 ~ SW4 是电平输入，
拨上为 1、拨下为 0。约束写进 `constr/hdmi_mm_player.adc`：

```tcl
set_pin_assignment { key_auto } { LOCATION = C8; IOSTANDARD = LVCMOS33; PULLTYPE = NONE; }
```

## 实现

### 1. 顶层：复用已有的按键消抖

`rtl/hdmi_mm_player.v` 新增输入 `key_auto`，用工程里已有的
`button_debounce`（`DEBOUNCE_CYCLES = 500000`，50 MHz 下 10 ms）把它变成
一个稳定的电平，而不是直接用引脚：

```verilog
button_debounce #(.DEBOUNCE_CYCLES(500000)) u_auto_switch (
    .clock (sys_clk), .reset_n (sys_rst_n),
    .button_n (~key_auto), .pressed_tick (),
    .stable_n (auto_switch_n)
);

wire auto_rotate_en = ~auto_switch_n;
```

`button_debounce` 是按"低有效按键"写的，所以这里取反一次；`reset_n` 后
`stable_n` 为 1（未按下），于是 `auto_rotate_en = 0`，上电一定是手动。

### 2. `player_ctrl`：手动时把保持计时器按在 0

`rtl/player_ctrl.v` 新增端口 `auto_rotate_en`。原来只有两个换页来源：

```verilog
// 自动轮播
else if (timer == HOLD_CYCLES) swap_wanted <= 1'b1;
// 手动按键
if (key_pressed) swap_wanted <= 1'b1;
```

现在自动那一路加上使能，手动时把计时器清零：

```verilog
if (key_pressed || (auto_rotate_en && (timer == HOLD_CYCLES)))
    swap_wanted <= 1'b1;

...
else if (!auto_rotate_en) timer <= 28'd0;   // 手动：停表
else if (timer != HOLD_CYCLES) timer <= timer + 28'd1;
```

这样处理有两个好处：

- 手动模式下停多久都不会累积计数，更不会自己换图；
- 拨回自动时是从 0 开始重新数满一个 6 秒周期，不会"拨上去马上跳一张"。

三个使用计时器的分支（cache 保持、preload 保持、非 cache 分支）都做了
同样的处理，历史配置不会被改坏。`KEY1` 的换页请求与计时器完全独立，
所以两种模式下按键行为一致。

### 3. `ui_overlay`：左上角多一个模式字符

`rtl/ui_overlay.v` 新增 `auto_mode` 输入，两级同步后在左上角面板的第 13 格
显示模式字符，原来那行文字不变：

```verilog
4'd13: top_char = auto_mode_value ? 8'h41 : 8'h4D; // A / M
```

所以画面上看到的是 `ANLU TIS 1/6 A`（自动）或 `ANLU TIS 1/6 M`（手动）。
第 13 格仍在面板宽度内（14 格），没有和右下角的波形 / 频谱重合。

### 4. 四个 ADV wrapper

`hdmi_adv01_subtitle.v`、`hdmi_adv02_fade.v`、`hdmi_adv03_scale.v`、
`hdmi_adv04_voice.v` 都加上 `key_auto` 输入并透传到 `hdmi_mm_player`。
当前工程的顶层是 `hdmi_adv04_voice`，其余三个保持可以单独综合。

音频、淡入淡出、双线性缩放、参数调节、波形 / 频谱叠加都没有改动；
切图仍然只切换 SDRAM 显示槽，所以人声播报不会因为切图重新开始。

把保持周期缩短后用六条检查覆盖开关语义：

1. 手动模式下把计时器放过头，不允许出现 `swap_req`；
2. 手动模式下按 `KEY1` 立即换图；
3. 打开自动后，下一次换图恰好在一个完整保持周期之后；
4. 切回手动后不再换图；

## 上板步骤

1. 用 TD 的 `PROGRAM_SRAM` 下载，**不要**用 `PROGRAM_FLASH`；
2. 先不拨 `SW1`：画面应停在当前图片不动，左上角是 `ANLU TIS n/6 M`，
   按 `KEY1` 能切下一张，`LED1` 闪一下作为按键确认；
3. 把 `SW1` 拨上：约 6 秒自动换一张，左上角变成 `... A`；
4. 拨回 `SW1`：应立刻停止自动换图（当前这张继续显示）；
5. 全程人声播报不能被切图打断，第一遍播完到第二遍开口仍是约 60 秒。

注意 `PROGRAM_SRAM` 下载后不要断电、不要按电源开关，否则板子会从配置
flash 重新加载旧设计。

## 已知边界

- `SW1` 现在是模式开关，因此不再保留它原来在官方例程里的用途；
- 模式切换只在 `player_ctrl` 的保持计时上生效，已经发出的换页请求不会
  被撤销，所以从自动拨回手动的瞬间如果正好在换页，会看到这一张切完再停；
- 手动模式下图片不切换，TF 卡的读取（预装下一张）仍然照常进行，
  按 `KEY1` 时通常只等一个视频帧。
