# ADV21 火灾紧急模式（2026-10-05）

> 注意：本文档的第 2 节（手画的火灾画面）和第 3 节（蜂鸣器节奏）已被
> `ADV22_火灾图片TF_20261005.md` 取代——火灾画面改成 TF 卡上的
> `EMGFIRE.BMP` / `EMGEXIT.BMP`，蜂鸣器改成双音警报，数码管显示 `119`。
> 串口命令、触发链路和引脚这几节仍然有效。

## 1. 这一步做了什么

新增一路**火灾紧急模式**：只要上位机（E104 蓝牙链路）报出火焰报警，
播放器立刻进入紧急状态，三块东西同时动作：

| 部位 | 报警时的表现 |
| --- | --- |
| HDMI 屏幕 | 全屏切成火灾疏散画面，盖住当前图片 |
| 板载蜂鸣器 | 三短响 + 停一秒，循环的火灾警报节奏 |
| 8 位数码管 | 闪烁显示 `FIRE` |

报警解除（上位机点"危险已解除"）后，画面、蜂鸣器、数码管全部回到原状态，
播放继续，不用重启，也不用重新读卡。

版本号从 `v1A` 提到 `v1B`。上位机状态栏能看到 `0x1B`，说明板子里烧的是
这一版固件。

## 2. 屏幕上的火灾画面

`rtl/ui_overlay.v` 增加一个 `emg_fire` 输入，报警时在原来所有图层之上
再铺一层全屏画面：

- 上下两条黄黑警示条纹
- 深红 / 亮红来回闪动的背景
- 顶部白色大字 `FIRE`
- 中间黄色警告三角，三角里是深色描边的火焰图形
- 底部一行 `EVACUATE NOW`

图案全部用比较器和工程里已有的 8x8 字库画出来，**不新增图片 ROM、
不占 BRAM**。这层画面优先于图片、航班看板、OSD、音频频谱，报警时
屏幕上只会看到疏散提示。

## 3. 蜂鸣器

蜂鸣器接在 `H11`，低电平响，报警节奏是：

```text
响 0.25 s -> 停 0.25 s -> 响 0.25 s -> 停 0.25 s -> 响 0.25 s -> 停 1 s -> 循环
```

音调是 1.5 kHz 方波。这样无论板上装的是无源蜂鸣器（方波直接发声）还是
有源蜂鸣器（被方波斩成断续警报），都能听出"报警"的效果。

## 4. 数码管

8 位数码管按 6.1 kHz 动态扫描，报警时 `SEL3/SEL4/SEL5`（左起第 4/5/6 位，
实物的中三位）闪烁显示 `119`，无报警时全灭。

手册第 15 页原理图显示位选经过 PNP 三极管驱动（发射极接 `DIGVCC`），所以
实物是**低电平选中**，正文写的“高电平有效”与原理图不符；第 16 页表格同时
说明 `SEL0` 是最左边第 1 位数码管。无报警时位选和段码都输出高电平，数码管
全灭。双色 LED 阵列复用同一组引脚且为高电平点亮，所以火灾演示必须把 `SW6`
拨上（数码管档）；拨下会切到 LED 阵列。

## 5. 串口命令

`rtl/uart/uart_ctrl.v` 新增一条命令：

| 命令 | 名字 | 载荷 | 回复 |
| --- | --- | --- | --- |
| `0x23` | `EMG` | `00` 正常 / `01` 火灾 | `A3 emg` |

命令由 `A5 5A` 帧头 + 长度 + 异或校验的原有协议承载，和 `TIME 0x22`
完全一致。

## 6. 报警从哪里来

真正的触发源是 E104 板上的火焰传感器，流程是：

```text
E104 火焰传感器 -> 蓝牙 -> 上位机 _emg_status["flame_alarm"]
                -> 包装器补丁 -> 串口 0x23 -> HDMI 板
```

`host/e104_time_sync_launcher.py` 里加了透明桥接：

- 原来 E104 上位机的任何文件都没有改动，包装器只是挂了一层回调
- 火焰报警一变就立刻发 `0x23`
- 每 5 个心跳重发一次当前状态，防止 FPGA 重新上电后状态丢失
- 先查固件版本，低于 `0x1B` 绝不发这条命令，避免旧板子收到未知指令

## 7. 手动演示（不接 E104 也能试）

`host/emg_test.py` 可以直接通过主串口发命令：

```powershell
python host\emg_test.py --state on
python host\emg_test.py --state off
python host\emg_test.py --state on --port COM6
```

脚本会先 `PING`，确认固件版本不低于 `0x1B` 再发命令。不带 `--port`
时自动挑第一个 CH340 / USB 串口。

## 8. 板子上的开关

| 开关 | 位置 | 作用 |
| --- | --- | --- |
| `SW5` | 拨下 | 接通蜂鸣器 |
| `SW6` | 拨上 | 选数码管（拨下是双色 LED 档） |

`SW5` 不拨下蜂鸣器不会响，`SW6` 不拨上数码管不会亮，这两个都不是代码问题。

## 9. 引脚

依据《HX4S20开发板手册-HDL版2410.pdf》：

| 信号 | 引脚 | 说明 |
| --- | --- | --- |
| `buzzer` | `H11` | 低电平响 |
| `seg_n[0..7]` | `C15 C16 B6 A5 B5 A8 A7 A6` | `a b c d e f g dp`，低有效 |
| `sel[0..7]` | `F16 E16 E12 E10 C13 F10 E11 D11` | 位选，低有效（板载反相驱动；手册表格写“高有效”，与实物不符） |

约束都在 `constr/hdmi_mm_player.adc` 里。

## 10. 构建与验证

- 构建脚本：`scripts/manual_build_adv21_emergency.tcl`
- 仿真渲染：`sim/tb_emg_dump.v` + `scripts/make_emg_preview.py`，
  生成的 `build/emg_preview.png` 确认 `FIRE`、`EVACUATE NOW`
  和警告三角都完整清晰
- 桥接自测：`python host/e104_time_sync_launcher.py --selftest`

TD 实际构建结果：

| 项目 | seed 4（不用） | seed 1（最终版） |
| --- | --- | --- |
| bit 文件 | `hdmi_adv21_emergency.bit` | **`adv21_seed1.bit`** |
| Setup | 6 条违例，最差 -0.349 ns | 0 违例，最差 +0.203 ns |
| Hold | 0 违例，+0.022 ns | 0 违例，+0.024 ns |
| Slice 占用 | 9711 / 9800，99.09% | 9685 / 9800，98.83% |

seed 4 的 setup 违例落在 FAT32 目录扫描路径上，与火灾功能无关，是新增
逻辑把器件推到接近满占用后布局被挤的结果。换成 seed 1 重跑后，setup 和
hold 全部收敛到 0 违例，最终烧录用 `adv21_seed1.bit`。
