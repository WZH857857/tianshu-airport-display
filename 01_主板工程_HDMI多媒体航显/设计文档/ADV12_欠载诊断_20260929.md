# ADV12 彩点定位：显示读 FIFO 欠载粘滞诊断（2026-09-29）

## 1. 为什么要做这一步

第 5/6 张图片在电视上密布彩点，而磁盘上的源 BMP 本身是干净的，排除了
"图片自带颗粒"这一项。回到 RTL，唯一会凭空造出彩色像素的路径只有一条：

`rtl/sdram/frame_store.v` 在显示 FIFO 读空（欠载）时，会立刻把
`pattern_pixel` 的兜底彩条像素送到画面上，而不是保持上一个像素。用户看到
的单像素彩色亮点正好符合这个特征。

问题是 `pix_underflow` 每个视频帧边界都会被清掉，而且只维持一个像素时钟，
肉眼、LED 和上位机都看不到。所以这一版加一个"粘滞"位，把"从上电到现在
到底有没有发生过欠载"记录到 LED 上。

## 2. 改了什么

| 文件 | 改动 |
| --- | --- |
| `rtl/sdram/frame_store.v` | 新增 `pix_underflow_seen`，复位清 0，一旦发生欠载永久置 1；复用它原本恒 0 的 `cal_fail` 输出端口 |
| `rtl/hdmi_mm_player.v` | LED 字最高位（`LED4`）或上 `cal_fail`，无语音故障时直接可见 |

没有改动 UART 协议、BMP 载入、缩放、淡入淡出、音频和 OSD，功能与 ADV11 一致。

## 3. LED 怎么读

启动双闪（四灯亮 0.5 s -> 全灭 0.5 s -> 四灯再亮 0.5 s）保持不变。
之后按 `LED4 LED3 LED2 LED1` 读状态字：

| LED 字 | 含义 |
| --- | --- |
| `0010` | 正常显示真实图片，本次上电以来没有发生欠载 |
| `1010` | 正常显示真实图片，但本次上电以来**至少发生过一次欠载** |
| `0001` 等 | 与 ADV11 相同的初始化/文件错误状态码 |
| 四灯交替闪烁 | 语音通路故障分页，与 ADV11 相同 |

`KEY1` 的短亮确认、启动双闪都不会清掉这个粘滞位，只有按 `B1` 复位（或重新
上电）才会清 0。

## 4. 上板对照实验

1. 烧录 `hdmi_adv12_ufdiag.bit`（下载选 `PROGRAM_SRAM`，时钟 5 MHz），确认
   看到启动双闪，说明板子上跑的是这一版。
2. `SW1` 拨下手动模式，让第 5 张或第 6 张静止显示，看彩点是否继续变多，
   同时记录 LED 字。
3. `SW1` 拨上自动轮播，观察切图瞬间彩点是否变化，LED 是否跳到 `1010`。
4. 拔掉 TF 卡后重新上电，看兜底彩条上是否也有彩点。
5. 按 `B1` 复位，看点是否清零后重新慢慢变多。

## 5. 结果怎么判读

| 现象 | 结论 | 下一步 |
| --- | --- | --- |
| 彩点出现时 LED 变成 `1010` | 就是显示读 FIFO 欠载，兜底彩条像素上了屏 | 提高读突发优先级 / 加深读 FIFO，或让欠载时保持上一像素 |
| 彩点持续变多但 LED 始终 `0010` | 不是欠载；主疑点转向 SDRAM 读采样相位或数据保持 | 调 `mem_clk_sft` 相位、降 SDRAM 频率做对比 |
| 兜底彩条上也有彩点 | 与 BMP 载入通路无关，指向 SDRAM 或 HDMI 下游 | 查 TMDS、排线、电视输入设置 |
| 复位后点从零重新变多 | 与温度/数据保持相关 | 优先查 SDRAM 刷新和采样相位 |
| 静止显示时点位置固定且不增加 | 更像源内容或缩放插值 | 换一张图对比确认 |
