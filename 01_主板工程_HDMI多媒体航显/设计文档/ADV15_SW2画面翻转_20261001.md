# ADV15 SW2 画面翻转（2026-10-01）

## 1. 这一步做了什么

板载 `SW2` 现在控制显示方向：

| SW2 | 含义 | 画面 |
| --- | --- | --- |
| 拨下（0，上电默认） | 正常 | 图片按原来的方向显示 |
| 拨上（1） | 翻转模式 | 同一张缓存图片上下翻转后显示 |

翻转只改显示侧的 SDRAM 读地址映射，**不重新读卡、不重新装载图片、不重启
播放状态**：切图、淡入淡出、人声播报、机场提示音、实时航班看板、分辨率
OSD、音频波形 / 频谱、HDMI A + B 双口输出全部照常。拨开关时音乐不会
重置，图片也不用重新从 TF 卡读。

版本号从 `v14` 提到 `v15`，上位机状态栏的"版本"可以直接确认烧进去的是
这一版。

## 2. 开关与引脚

依据《HX4S20开发板手册-HDL版2410.pdf》第 18 页图 2-19 与"乒乓开关引脚"
表：`SW1 = C8`、`SW2 = C7`、`SW3 = C6`、`SW4 = C5`，四个开关都是
**拨上为 1、拨下为 0** 的电平输入。

| 开关 | 引脚 | 本工程用途 |
| --- | --- | --- |
| `SW1` | C8 | 切图模式：拨下 = 手动（上电默认，按 `KEY1` 切图），拨上 = 自动轮播 |
| `SW2` | C7 | 画面方向：拨下 = 正常，拨上 = 上下翻转 |
| `SW3` / `SW4` | C6 / C5 | 本版未使用 |

约束文件 `constr/hdmi_mm_player.adc` 里 `key_flip` 就挂在 `C7`，
`IOSTANDARD = LVCMOS33`、`PULLTYPE = NONE`，与 `SW1` 的接法一致。

## 3. 实现方式：读侧地址映射

图片仍然按原来的方式缓存在 SDRAM 的六个图片槽里，画面数据通路一个字都
没变，改的只是"按什么顺序把这一帧读出来"：

```text
正常：stream line 0   -> memory line 0     （行内从左到右）
翻转：stream line 0   -> memory line 479   （行内仍从左到右）
      stream line 1   -> memory line 478
      ...
```

具体落在 `rtl/sdram/vendor/frame_fifo_read.v`：

- 请求应答状态 `S_ACK` 里采样一次 `read_v_flip`，和帧基地址一起锁存，
  所以开关的变化**只在帧边界生效**，绝不会把一帧读到一半换映射；
- 翻转帧的起始地址是最后一行的行首，行内每次 `+1`，一行读完再跳回上一行
  的行首，跳距 `2 * FRAME_WIDTH - 1`；
- 每帧读取的字数完全不变（640 x 480 个 32 bit 字），异步 FIFO 的握手、
  深度、突发长度都不动。

顶层 `rtl/hdmi_mm_player.v` 把 `SW2` 接进与 `SW1` 相同的 10 ms 按键消抖，
再在 `mem_clk`（125 MHz）域做两级同步送进读调度器。`frame_store.v` 只
负责把这根电平随图片槽一起传给读调度器，不参与地址计算。

相对 ADV13/ADV14 版本，综合出来的增量是 **+90 个门、+43 个触发器**，
属于很小的改动；时序上新增的路径在 125 MHz 域只有 8 ns 预算，真正卡住
整板时序的仍然是 `bmp_scaler` 里那条原有的 50 MHz 长链。

## 4. 上板怎么验收

1. 烧 `adv15_flip_seed4_pass.bit`（桌面另存了一份
   `天枢空港智显_SW2翻转_v15_seed4.bit`）。下载方式选 `PROGRAM_SRAM`，
   时钟 5 MHz。
2. 打开上位机，连串口。状态栏"版本"应显示 `v15`。
3. `SW2` 拨下 -> 画面正常；拨上 -> 同一张图上下翻转。来回拨几次：
   图片不能重新装载、音乐不能重启、当前图片不能变。
4. 在翻转状态下按 `KEY1` 切图 / 等自动轮播 / 改航班看板文字，切换后的
   新图片仍应保持翻转方向。
5. 顺带回归：人声播报 60 秒循环、淡入淡出、分辨率 OSD、波形 / 频谱、
   HDMI A + B 两块屏同步显示。

## 5. 关于"竖屏"，必须说清楚的三件事

**这一版做的是上下翻转（上下镜像），不是 90 度旋转。** 三种实际用例对应
完全不同的做法：

| 实际要做的事 | 现在这版够不够 | 说明 |
| --- | --- | --- |
| 屏正常横放，要显示竖版海报 / 竖版航显 | 够 | 不需要旋转：把竖版图做成 640 x 480 画布（左右留黑边）放进 TF 卡即可，`SW2` 保持拨下 |
| 屏是倒吊 / 转 180 度安装 | 不够 | 倒装需要 **180 度旋转**（上下翻转 + 左右翻转）。现在只翻了上下，会得到镜像画面。补左右翻转是同一处改动（读地址改成行内反向、行末跳距改成 `+W+1`），重新构建约半小时 |
| 电视要竖着装（转 90 度） | 不够 | 竖装需要真正的 **90 度旋转**：SDRAM 里得按转置地址写入、再按行按序读出，等于新增一个转置写入引擎，并且要把 640 x 480 的整块缓存搬一遍。在 97% 的资源余量下这是一次不小的改动，需要单独排期 |

结论：如果验收时屏是竖着装的，先告诉我是"竖装"还是"倒装"，我按哪一种去补；
如果屏是横放、只是要让画面看起来像竖版航显，用 640 x 480 画布加黑边最省事，
也不用再动 FPGA。

## 6. 构建与时序

这块板子（EG4S20，9800 slice）在 ADV13 之后资源就已经到 95% 上下，布线
对布局种子非常敏感，所以这次照旧用种子扫描挑一个时序全绿的布局：

| 种子 | 建立余量 WNS | 建立违例端点 | 保持余量 WNS | 保持违例端点 | slice | 结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | -506 ps | 6 | +24 ps | 0 | 97.57% | 失败 |
| 1（ADV13/ADV14 用过的种子） | -146 ps | 1 | +24 ps | 0 | 97.03% | 失败 |
| 2 | -132 ps | 3 | +27 ps | 0 | 97.12% | 失败 |
| 3 | -1133 ps | 8 | +24 ps | 0 | 98.04% | 失败 |
| **4** | **+220 ps** | **0** | **+30 ps** | **0** | **97.09%** | **通过** |

最终交付：

| 项目 | 结果 |
| --- | --- |
| 位流 | `hdmi_adv15_flip.bit`、`adv15_flip_seed4_pass.bit` |
| 大小 | 630 801 字节 |
| SHA256 | `9A7EEDCC42DE4DDCB2066DEDB98F7209B346B8D1101DBC4262ED34DF3EA40B89` |
| 生成时间 | 2026-10-01 00:00:52 |
| 布局种子 | `place seed 4` |
| 建立余量 | +220 ps，0 个违例端点 |
| 保持余量 | +30 ps，0 个违例端点 |
| 资源 | 9 515 / 9 800 slice（97.09%）、28 BRAM、20 DSP |

回退位流仍然是 ADV13/ADV14 的 `adv13_seed1_pass.bit` / `hdmi_adv13_board.bit`
（+181 ps，9357 slice），它没有 SW2 翻转功能，其它功能与 ADV15 一致。

种子扫描脚本 `scripts/run_adv15_seed_sweep.ps1` 已经补上一个坑：
`td_commands_prompt.exe` 是交互式命令行，tcl 跑完后会停在 `td >` 提示符
等输入，从带终端的会话启动会一直挂着。现在脚本用 `< NUL` 喂 EOF，跑完
一个种子自动退出、解析 `route.qor`、判断是否全绿，第一个通过的种子会
自动另存位流并停止。

```text
C:\iverilog\bin\iverilog.exe -g2012 -o sim\tb_frame_fifo_read_flip.vvp ^
    sim\tb_frame_fifo_read_flip.v rtl\sdram\vendor\frame_fifo_read.v
C:\iverilog\bin\vvp.exe sim\tb_frame_fifo_read_flip.vvp

C:\iverilog\bin\iverilog.exe -g2012 -o sim\tb_frame_store_official.vvp ^
    sim\tb_frame_store_official.v rtl\sdram\frame_store.v ^
    rtl\sdram\vendor\frame_read_write.v rtl\sdram\vendor\frame_fifo_read.v ^
    rtl\sdram\vendor\frame_fifo_write.v rtl\sdram\vendor\afifo_16_32_256.v ^
    rtl\sdram\vendor\afifo_32_16_256.v sim\sdr_as_ram_stub.v
C:\iverilog\bin\vvp.exe sim\tb_frame_store_official.vvp
```
