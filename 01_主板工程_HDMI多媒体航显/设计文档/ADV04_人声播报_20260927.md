## 1. 目标

ADV02-A 交付的片内提示音解决了"切图不重置音乐"，但它是纯音，不是广播。
本轮要把音频换成**机场提醒旅客的那种人声播报**，同时保住前几轮的两条约束：

1. 人声必须能通过 HDMI 从显示器扬声器放出；
2. 切图（KEY1 手动切图 / 6 秒自动轮播）**不能**让人声从头重播。

## 2. 数据通路

人声和图片共用同一个 FAT32 读卡器，分时使用：上电先把六张图片读进 SDRAM，
缓存完成后才启动人声流。（下面第一段是 09-27 的音库版通路，已被 09-28 的
流式通路取代。）

```text
TF 卡根目录第一个 .WAV
  -> fat32_file_reader（load_voice 阶段，8.3 短名扫描）
  -> wav_voice_loader
       RIFF / fmt / data 解析，16 位或 8 位 PCM、单声道或立体声
       G.711 mu-law 压缩（16 位 -> 8 位，同样容量多存一倍时长）
  -> voice_bank（40960 x 8，写侧 50 MHz / 读侧 12.288 MHz）
  -> voice_player（48 kHz 帧节拍，16.16 相位累加 + 4 点插值重采样）
  -> hdmi_audio_tone_i2s_64fs（I_voice_en 有效时人声完全接管 I2S）
  -> 官方 HDMI 1.4b audio island -> HDMI_A
```

现在的流式通路（`hdmi_adv05_stream.bit`）：

```text
TF 卡根目录第一个 .WAV
  -> fat32_file_reader（图片缓存完成后的 voice 阶段，8.3 短名扫描）
  -> wav_voice_stream
       边读边解析 RIFF / fmt / data，16 位或 8 位 PCM、单声道或立体声
       G.711 mu-law 压缩，一个样本一个字节
  -> 1024 字节异步 FIFO（写侧 50 MHz 卡时钟 / 读侧音频时钟）
  -> voice_player_stream（48 kHz 帧节拍，16.16 相位累加 + µ-law 解码）
  -> hdmi_audio_tone_i2s_64fs（人声有效时完全接管 I2S）
  -> 官方 HDMI 1.4b audio island -> HDMI_A
```

人声载入完成后 `voice_ready_sys` **只升不降**，经双打拍同步到音频时钟域；
播放相位只由 `audio_mclk` 推进。切图路径只产生 `frame_swap_done -> cue_tog`
这一根提示音混音信号，`I_voice_en` 有效时被 `hdmi_audio_tone_i2s_64fs`
直接忽略，所以"切图不重置人声"是从结构上保证的，不是靠时序绕开的。

人声使能后片内 E5/C5 循环提示音不再出声，因此**提示音录进了 WAV 开头**，
听感仍是机场那套"叮咚 + 中文播报"。

## 3. 调试中修掉的问题

### 3.1 `wav_voice_loader`：WAV 解析

| 现象 | 根因 |
| --- | --- |
| RIFF/chunk size 全部解析错 | 小端数值按大端拼装，标签和数值需要两种拼法 |
| EXTENSIBLE 文件字段错位 | 16 字节普通 fmt 与 26 字节扩展 fmt 的切片基准不同，需先左对齐补齐 |
| fmt 长度判断用错寄存器 | `S_CSIZE` 里用了尚未更新的 `chunk_size`，应当用本拍 `chunk_val` |
| 16 位立体声直接死锁 | `frame_bytes` 只有 2 bit，`4` 被截断成 `0`，`bcnt` 扩到 3 bit |
| 每个 chunk 边界吃掉一个字节 | chunk 切换那一拍不算数据，新增 `S_PAUSE` 空一拍 |
| 奇数长度 chunk 后错位 | skip 计数要把 pad 字节一起算进去 |

### 3.2 `voice_player`：读时序与增益位宽

- **同步 BRAM 读数据晚一拍**，原来在同一个状态采数会把上一拍的数据当成当前
  样本。改成 `VS_PRE`（发首地址）-> `VS_RD0`（发第二地址）-> `VS_RD1`
  （采 s0、锁 frac）-> `VS_CALC`（采 s1）-> `VS_MIX`（输出），状态位宽 2 -> 3。
- **gap 段每个音频时钟都清零样本**，把刚生成的最后一个样本冲掉了；改成只在
  `frame_tick` 时清零。
- **增益寄存器位宽不够，满幅样本全部回绕**（第一次上板后定位的主 Bug）。
  `gained` 原来是 `wire signed [17:0]`，µ-law 解码满幅 32124 左移
  `GAIN_SHIFT=7` 之后是 4111872，18 位放不下，大声样本折回负值。修法是先把
  插值结果符号扩展成 24 位再移位，`VS_MIX` 直接输出 `gained`。离线黄金模型
  与仿真台逐项对照如下：

  | 模型 | 峰值 | 非静音帧 | 幅度 > 100000 的帧 |
  | --- | --- | --- | --- |
  | 修复后 24 位 | 2932224 | 26119 | 21189 |
  | 原 18 位截断 | 131072 | 26111 | 5486 |

  修复前 e2e 实测 `peak 131072 / active 26111`，与 18 位模型吻合，说明测试台
  对位正确；修复后实测 `peak 2932224 / loud 21189 / active 26119`，同样与模型
  吻合。`tb_voice_player` 并联了一段 `GAIN_SHIFT=7` 的实例，断言
  `0xCE -> 126464`、`0xA0 -> 1015296`、`0x80 -> 4111872`、`0x00 -> -4111872`，
  老代码会在这里报 FAIL。

### 3.3 音库把 BRAM 撑爆（`PHY-9013`）

```
PHY-9013 ERROR: Design's emb number = 84, exceeds the limit 64.
```

TD 是按**地址端口宽度**推断 RAM 深度而不是按数组边界：一个 40960 深的
`reg [7:0] mem [0:40959]` 被推断成 65536 x 8，映射成 64 块 9 Kb BRAM，
加上显示通路本来就用的 20 块正好 84 块。

修法是把音库拆成 32768 + 8192 两段，同一份 40960 样本只占 32 + 8 = 40 块，
整机降到 **60 / 64**。两个数组每拍同时读，用延迟一拍的地址位选输出，
读延迟与原来的单数组完全一致。

### 3.4 µ-law 编码器压在关键路径上

加完人声后第一次布局的最终布线时序：

```
Slack   : -4.471ns      Budget: 20.000ns
Begin   : u_player/u_fat32/state_reg[*].clk
End     : u_player/u_voice_bank/ramread0_syn_58.dia[1]   <- BRAM 写数据脚
Logic   : 24 levels ( LUT4=6 ADDER=6 LUT5=5 LUT3=5 EMB=1 DRAM=1 )
```

FAT32 状态 -> 扇区 RAM -> 字节拼装 -> µ-law 编码器 -> BRAM 数据脚全挤在
一个 50 MHz 周期里。在 `wav_voice_loader` 里加一级写流水（样值先寄存，
下一拍再编码写库），字节握手和写入吞吐都不变：

| 版本 | gate WNS | place WNS | 最终布线 WNS |
| --- | --- | --- | --- |
| 单数组 65536 深 | -8482 ps（BRAM 超限） | 失败 | 失败 |
| 拆库，编码器仍在路径上 | — | +1877 ps | **-4471 ps（违例）** |
| 拆库 + 写流水（交付版） | -2525 ps | +3041 ps | **+179 ps（0 违例，place seed 2）** |

作为对照，上一版可用的 `hdmi_adv02_fade.bit` 最终 WNS 是 +374 ps。

## 7. 上板步骤

1. **TF 卡根目录同时放 `IMG01.BMP` ~ `IMG06.BMP` 和 `VOICE.WAV`**（直接把
   `sdcard\` 里的全部文件拷到根目录），不要放子文件夹。第一次上板只听到片内
   提示音，就是因为卡上漏了 `VOICE.WAV`：没有这个文件时顶层直接跳过人声阶段，
   听感和"人声坏了"完全一样。文件名用 8.3 短名（`VOICE.WAV` 即可），
   根目录里第一个 `.WAV` 会被选中。
2. 烧 `hdmi_adv04_voice.bit`（**不是** `backup\...\*_gainfix_seed1.bit`，
   那一版时序违例）。
3. HDMI 接**带扬声器**的显示器/电视，预期听到：E5 -> C5 叮咚，接着中文播报
   "前往北京的旅客请注意，请到3号登机口登机"，播完静音 1.5 秒再循环。
4. 播报过程中按 KEY1 切图，人声应当**不中断、不从头重放**。

如果放好文件、烧好新位流仍然没有人声，看板上的四灯：正常的负载状态码一闪一灭
表示"人声阶段已结束但音库为空"，闪烁的那个字就是故障码（判读表见 `README.md`
的"人声位流的状态页"）。最常见的两种：

- `0001`：根目录里没找到 `.WAV`（文件名或位置不对）；
- `1xxx`：文件被载入器拒绝，`xxx` 是错误码（1 = 非 RIFF / 2 = 不支持的 fmt /
  3 = 无 data 块 / 4 = 文件为空 / 5 = 读卡流失败）。WAV 必须是 8 位或 16 位
  PCM，或 8 位 µ-law；24 位和浮点 WAV 会被判成 `010`。

## 8. 已知限制

- **第一次上板（21:42 那版位流）只听到片内提示音**，事后定位到两个原因：
  卡根目录没放 `VOICE.WAV`（人声阶段被跳过，退回片内提示音），以及
  `voice_player` 的 18 位增益寄存器把大声样本截断回绕（见 3.2）。两条都已
  修复，但**修复版位流尚未上板**，实际响度、音色和"切图不重置"仍需实测确认。
- （音库版限制，流式版已解除）音库固定 40960 个样本，8 kHz 素材最长 5.12 秒，
  16 kHz 素材最长 2.56 秒，超出的尾部会被丢弃。流式版没有这个上限，
  `sdcard\VOICE.WAV` 现在是 920 471 个样本 / 115.06 秒。
- 人声接管后片内提示音不再出声，提示音是录在 WAV 里的，换素材时别丢。
- 音库版最终建立余量 +179 ps 偏薄（基线 ADV02 是 +374 ps）；流式版把
  FAT32 侧的输入字节先打一拍（`wav_voice_stream` 的 `in_data` / `in_valid`），
  那条 22 ns 的组合路径消失，因此同样的 FAT32 状态机路径在 seed 4 下有
  +168 ps 余量。如果上板出现图片加载不稳，可以跑 `scripts\try_adv01_seeds.ps1`
  那套换 place seed 重做。
