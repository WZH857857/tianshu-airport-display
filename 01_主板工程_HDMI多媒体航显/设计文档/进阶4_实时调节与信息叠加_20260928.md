## 2. 缩放质量：双线性插值

### 2.1 算法

`rtl/storage/bmp_scaler.v` 把任意尺寸的 BMP 映射成 640 x 480，映射公式是
中心对齐的

```text
源位置 = (目的位置 + 0.5) * 源尺寸 / 目的尺寸 - 0.5
```

源尺寸和目的尺寸都是运行期才知道的，所以除法被写成"商 + 余数"定点形式：
相位用 `2 * 目的尺寸` 做分母，商用三次比较减法（4 倍、2 倍、1 倍）归一化，
权重是常量除法（分母在综合期就是常数）。一路是水平插值写行缓存，
另一路是垂直插值读两支行缓存，两次插值的舍入方式与测试台的参考模型逐点一致。

### 2.2 时序问题与修法

第一版把水平插值结果直接连到行缓存的写数据口，关键路径因此是

```text
w_src_reg -> 边界比较 -> 权重 -> 9x8 乘法 -> 截断 -> BRAM dia
```

布线后 QoR 为 `Setup WNS = -549 ps，TNS = -8785 ps，30 个违例端点`，
终点全是 `g_line_bram` 的 `dia`，即 BRAM 写数据输入。

修法是把写口全部寄存一拍：

1. `ST_HWR` 里把插值结果、目的列地址和缓冲选择分别锁进
   `h_mix_r / h_wr_addr / h_wr_buf`，并置起 `h_wr_pend`；
2. 行缓存实际写在下一拍，只由 `h_wr_pend` 拉高写使能；
3. 边界判断（第二个抽头 `h_x1`、越界标志 `h_edge`、垂直的 `v_y1 / v_same`）
   同样从组合逻辑改成寄存器，相位推进时锁存，行首重装时也锁存同一组初值。

改完后 `Setup WNS = +269 ps，TNS = 0，违例端点 0`。
插值结果在改动前后完全一致，四组几何回归都是 0 mismatch。

## 3. 按键与参数

### 3.1 按键分配

| 按键 | 引脚 | 功能 |
| --- | --- | --- |
| `KEY1` | A2 | 立即切到下一张图（不变） |
| `KEY2` | B2 | 调节 `KEY4` 选中的参数，每按一次走一格，端点回绕 |
| `KEY3` | - | 复位（不变） |
| `KEY4` | C1 | 短按切换参数；长按 1 秒切换叠加布局（不变） |

按键经过 `button_debounce`（10 ms）后才生效，长按和短按靠
`ui_hold_cnt` 的 1 秒比较区分：长按只切布局、不再切参数选择。

### 3.2 参数映射

| 参数 | 档位 | 映射 | 默认 |
| --- | --- | --- | --- |
| 亮度 | 0..7 | 5 位增益 `4/8/12/16/20/24/28/31`，再除 32 | 7（31/32） |
| 对比度 | 0..7 | `k = 10/12/14/16/18/20/22/24`，系数 `k/16` | 3（精确 1.00） |

对比度按 `out = (in - 128) * k / 16 + 128` 逐通道计算，并截断到 0..255；
它在亮度之前处理，所以两条链路不会互相改变对方的工作点。
亮度的 5 位增益和淡入淡出共用同一个乘法器，淡入淡出满档时总增益就是
`(31 * 亮度增益 + 31) >> 5`。

### 3.3 画面上的参数信息

`rtl/ui_overlay.v` 增加了一块参数面板：右上角 168 x 32 的位置，
原本显示机场时钟；`param_flash` 有效时改成显示参数读数，
底为压暗的底色，字为 `0xFFC000`（琥珀色）：

- `BRIGHT n`：`n` 是当前亮度档位；
- `CONTRAST n`：`n` 是当前对比度档位；
- `OSD FULL / INFO / ON / OFF`：长按 `KEY4` 切换布局时显示布局名。

读数显示 1 秒（`param_timer`，50 MHz 下 50 000 000 拍）后自动消失，
面板让位给时钟。`param_sel` 是两位：0 亮度、1 对比度、2 布局。

## 4. 验证

### 4.1 缩放

`tb_bmp_scale_chain` 用解析器 + 缩放器的真实链路，喂 640 x 480 恒等、
300 x 200 放大、960 x 720 缩小、641 x 481 奇数行填充四种尺寸，
逐点与参考模型比较：

| 用例 | 结果 |
| --- | --- |
| 640 x 480 恒等 | 307 200 像素，mismatch 0 |
| 300 x 200 放大 | 307 200 像素，mismatch 0 |
| 960 x 720 缩小 | 307 200 像素，mismatch 0 |
| 641 x 481 奇数行 | 307 200 像素，mismatch 0 |

两种行缓存实现都跑了两遍：推断式模型（`BRAM_PRIM=0`）和板级宏
（`BRAM_PRIM=1`，由 `sim/check_stubs.v` 提供行为级 `EG_LOGIC_BRAM`），
结果相同，都是 `RESULT: PASS`。

### 4.3 按键与像素算术

`tb_param_control` 把整个顶层用 `sim/check_stubs.v` + `sim/sdr_as_ram_stub.v`
展开，按键从引脚驱动、经过真实消抖，检查：

- 复位默认值为亮度 7、对比度 3，且没有任何读数；
- `KEY2` 一次把亮度 7 -> 6，同时点亮 1 秒读数；
- `KEY4` 短按后选择变成对比度，`KEY2` 只动对比度、不动亮度；
- 亮度、对比度都在 0 处回绕到 7；
- `KEY4` 长按 1 秒后布局档位 +1、`param_sel` 变成 2（OSD 读数）；
- 读数定时器归零后 `param_flash` 拉低；
- `ui_overlay` 里采到像素时钟域的亮度/对比度/选择/读数窗口与
  `hdmi_mm_player` 中像素通路使用的寄存器完全一致（所以照片里的数字就是
  画面实际使用的数字）；
- 8 档对比度 x 10 组像素（含 0、1、127、128、129、255 等边界）逐点与
  `(in-128)*k/16+128` 的参考值比较，8 档亮度也按 `scale` 的参考值比较，
  对比度第 3 档必须精确等于输入。

结果：`PARAM CTRL TB: PASS`。

## 5. 上板步骤

1. TD 里选 `hdmi_adv07_bramscale.bit`，烧 `PROGRAM_SRAM`，不要烧 flash；
2. TF 卡根目录放 `sdcard\adv03_demo\` 的六个 BMP 和 `VOICE.WAV`
   （全部 ASCII 文件名，中文名会导致扫描不到）；
3. 屏幕出现图片后按 `KEY2`：右上角应显示 `BRIGHT n`，画面亮度随按动变化；
4. 短按 `KEY4` 再按 `KEY2`：读数变成 `CONTRAST n`，画面反差随按动变化；
5. 长按 `KEY4` 约 1 秒：显示 `OSD <布局>`，叠加层按原来的四种布局循环；
6. 切图（`KEY1` 或 6 秒自动轮播）时人声不应重新开始。
