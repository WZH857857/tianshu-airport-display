# 进阶 3：串口上位机实时控制（图片 + 文字）

2026-09-29

## 1. 目标与合规边界

赛题要求"参赛作品中所展示的所有算法、控制逻辑及数据处理流程应在 FPGA 中
自主编程实现……不得带有额外处理器（无论用于辅助控制还是算法预处理）"。

本方案的边界划得很清楚：

- **PC 只是遥控器和显示端**。上位机发出去的是**指令**，不是像素、不是码流。
- **板载 CH340 只是 USB-UART 电平桥**，把 USB 报文变成 3.3 V 串口时序，
  不理解也不参与任何图像逻辑。
- 真正的活全部留在 FPGA 里：读卡、FAT32、BMP 解析、SDRAM 双缓冲、淡入淡出、
  缩放、字幕字形渲染、音频解码与播放，一条都没有搬到 PC。

所以这套上位机等价于"把板上的 KEY1 和拨码开关搬到了电脑屏幕上"，属于人机
交互界面，不是额外处理器。

## 2. 硬件连接

板上丝印 `USB-UART` 的那只 Type-C 插座（原理图网络 `USB1`），同时也是供电口。

| 信号 | 方向 | 引脚 | 约束 |
| --- | --- | --- | --- |
| `uart_rx_pin` | CH340 TXD → FPGA | F12 | LVCMOS33, PULLUP |
| `uart_tx_pin` | FPGA → CH340 RXD | D12 | LVCMOS33, 8 mA |

引脚依据《HX4S20 开发板手册-HDL 版 2410》2.9 节。约束落在
`constr/hdmi_mm_player.adc`（新增两行）与 `constr/hdmi_adv11_uart.sdc`。
串口输入相对系统时钟是异步的，SDC 里对它做了 `set_false_path`，避免工具在
这条不可能收敛的路径上报违例。

## 3. 帧格式

双向同格式，一问一答：

```text
A5 5A | cmd | len | payload[len] | xor
```

`xor` 是 `cmd`、`len` 与全部 payload 字节的异或，**不含包头**。
`A5 ^ 5A = FF`，包头一旦混进校验就会让回包校验整体取反，这一点在仿真里
被专门盯住了（见第 6 节）。

| cmd | 名称 | payload | 回包 |
| --- | --- | --- | --- |
| 01 | PING | 无 | `81 ver` |
| 02 | TEXT | ASCII 0..32 字节，0 = 恢复内置字幕 | `82 eff_len text_len` |
| 03 | SLOT | 槽位 0..5 | `83 slot` / `E0 03 code` |
| 04 | MODE | 0 手动 / 1 自动 / 2 交回 SW1 | `84 mode` |
| 05 | PARAM | sel 0 亮度 1 对比度，val 0..7 | `85 sel val` |
| 06 | OSD | 布局 0..3 | `86 layout` |
| 07 | BAUD | 档位 0..4 | `87 index`（用**新**速率发出） |
| 10 | STATUS | 无 | `90` + 10 字节状态 |

错误回包统一 `E0 <cmd> <code>`：

| code | 含义 |
| --- | --- |
| 1 | 长度越界 |
| 2 | 槽位越界 |
| 3 | 槽位尚未缓存 |
| 4 | 未知命令 |
| 5 | 取值越界 |

STATUS 的 10 字节依次是：版本、当前槽位、文件总数、运行模式（0 手动 / 1 自动）、
亮度、对比度、OSD 布局、缓存位图（6 bit）、字幕长度、标志位（bit0 主机说过话、
bit1 TF 卡就绪）。

## 4. FPGA 侧实现

新增 `rtl/uart/`：

| 文件 | 职责 |
| --- | --- |
| `uart_rx.v` | 8N1 接收。三拍同步器消亚稳态，起始位中点复检防毛刺；`div` 是端口，可运行时改波特率 |
| `uart_tx.v` | 8N1 发送。`div` 在发送开始时锁存，避免换挡中途改分频；`busy`/`done` 握手 |
| `uart_ctrl.v` | 协议层：解析 → 校验 → 执行 → 回包 |

改动到的既有模块：

- `rtl/ui_overlay.v`：新增 32 字节主机字形缓冲。字节通过 toggle 握手从 50 MHz
  域搬进像素域，每字节间隔 16 个时钟，远大于两级同步器需要的时间；小写自动
  折成大写并补了 `J`、`Q` 两个字模；面板上多了一个 `U` 链路指示。
- `rtl/player_ctrl.v`：新增 `jump_req` / `jump_slot`，收到后走**与 KEY1 完全
  相同**的淡入淡出换页握手。这正是"切图不打断音频"的关键——换页路径从来
  不碰音频流。
- `rtl/sdram/frame_store.v`：新增定向跳转，优先于原来的轮转逻辑，且不受
  "首帧是否已上屏"限制。
- `rtl/hdmi_mm_player.v`：接入上述模块，并把 UART 的控制输出按优先级插进
  按键/参数状态机前面（串口优先）。

两条刻意设计的保护：

1. **TEXT 边收边送、校验通过才提交**。payload 一到就直接写进 `ui_overlay` 的
   那一份字形缓冲（`text_addr` / `text_data` / `text_tog`），但滚动字幕读的
   `host_len` 只在 `text_commit_tog` 的边沿更新；校验失败则 toggle
   `text_clear_tog`，画面退回内置字幕。撕裂的一帧永远不会上屏，32 字节缓冲
   也只存在一份——这是 ADV11 能塞进 97% 占用率的关键。
2. **回包期间挂起解析器**。一问一答的节奏下，上位机若抢发下一帧，字节只会
   被丢弃，不会污染状态机。

面积上的取舍（初版实现占 373 个触发器、时序不过，改完回到可收敛区间）：

| 项目 | 初版 | 现在 |
| --- | --- | --- |
| `uart_ctrl` 文本缓冲 | 自己存 32 字节（256 FF） | 直接写 overlay，0 份 |
| 回包 | `rep_data[0:15]` 数组 + 16 选 1 读 | 组合函数按 `bidx` 生成 |
| 总面积 | 9557 slice（97.52%） | 见第 6 节实测 |

## 5. 上位机

`host/airport_console.py`（PyQt5），`host/run_console.bat` 双击即可启动。

界面按"机场航显运维台"来做，三栏：

- **左栏**：串口选择（自动识别 CH340）、波特率、连接按钮；板卡状态卡实时显示
  版本、当前画面、运行模式、缓存进度、字幕长度、TF 卡状态；下面是目标板卡的
  静态信息（器件、输出时序、串口引脚、音频参数、协议版本）。
- **中栏**：六张画面的缩略图（取自 `sdcard/IMG01..06.BMP`）。已缓存的可点，
  没进缓存的自动置灰。下面是航显字幕输入框，带 32 字符计数和常用播报预设。
  底部是链路日志，TX 橙色、RX 青色、错误红色，每帧都带时间戳。
- **右栏**：上屏预览（把当前画面缩略图加上琥珀色滚动字幕条，按 4:3 比例画出
  板上实际的输出构图）、切图模式三态（手动 / 自动 / 跟随 SW1）、亮度与对比度
  滑条、信息面板布局四态、链路统计（TX / RX / 错误计数）。

视觉语言上按"航显运维台"收了一遍：品牌位是自绘的客机爬升徽标（跑道 + 客机，
同一枚图形也
用作窗口图标），头部带版本号和实时时钟；面板统一 8 px 圆角、1 px 描边、琥珀色
竖线标题；当前画面卡有"播放中"角标和琥珀色描边；已缓存槽位用进度条可视化；
上屏预览右上角是 LIVE 指示，画面 badge 在窄窗口下会自动退化成 `IMG0x`，不会和
LIVE 撞在一起。截图见 `host/ui_preview.png`（1420×900）与 `host/ui_min.png`
（1280×820，最小窗口）。

窗口默认 1420×900，最小 1280×820；`--demo` 会用一批示例状态把界面填满，
方便截图或写报告：

```powershell
E:\anaconda3_install\python.exe host\airport_console.py --shot host\ui_preview.png --demo
```

几个实现上的取舍：

- **字形集限定**。`ui_overlay.v` 的字模只有 `空格 - . / 0-9 : A-Z`，别的字符
  上屏就是空白。输入框自动转大写并剔除不支持的字符，被丢掉的字数会在提示行
  说明，避免"我明明打了字，屏幕上什么都没有"。
- **波特率切换不等于普通写**。`07 BAUD` 的回包是用**新速率**发出来的，
  115200 下一帧只有几百微秒，PC 来不及换挡。所以这里不等这个回包：发完命令、
  切到新速率、清空接收缓冲，然后用一帧 STATUS 在新速率上验证；验证不过就自动
  退回原速率并报错。
- **状态轮询**。空闲时每秒发一帧 STATUS，链路断了会立刻在右上角变"无应答"。
- **滑条防抖**。亮度/对比度拖动时 120 ms 合并一次，避免刷屏。

### 图片分辨率

界面上三处显示分辨率，取的都是本地槽位 BMP 的真实像素尺寸：

| 位置 | 形式 | 说明 |
| --- | --- | --- |
| 画面槽位卡缩略图下方 | `IMG03  640×480` | 每张卡显示自己那张图，未缓存的槽位照旧置灰 |

这里有一条必须说清楚的边界：**分辨率读的是 PC 侧那份 `sdcard/IMG0x.BMP`，

尺寸"，而板上缩放器把它统一成 640×480 输出（见左栏"板卡信息"的输出时序）。
真要板上 OSD 也显示分辨率，见第 7 节末尾。

## 6. 验证

### 协议仿真

`sim/tb_uart_ctrl.v` 用真实 8N1 波形跑 12 帧：PING、TEXT、SLOT（命中与未缓存
两种）、MODE 两态、PARAM 两路、OSD、STATUS、坏校验帧必须无回包、TEXT 撕裂帧
不得上屏、空 TEXT 复位。除了回包的头/长度/校验，测试平台还照 `ui_overlay` 的
做法搭了一份"暂存 + commit"的影子模型，检查搬运的字节内容、提交次数，以及
坏校验帧只清屏不提交。

仿真过程中抓到三个真问题：

1. **RTL 校验把包头算了进去**。`S_RCHK` 从 `rep_data[0]` 开始累加，`A5 ^ 5A = FF`
   让所有回包校验整体取反。测试平台从第一个字节就对不上，改成从 `rep_data[2]`
   开始累加后一致。
2. **测试平台自己的接收器早采一位**，把起始位当成 bit0，读出来正好是原值的
   移位结果（`A5 → 4A`）。采样点补一个位周期后正确。
3. **回包发送取的是下一个字节**。`S_TX` 里 `tx_issued` 分支用的 `bidx` 已经加过
   一跳，于是每个字节都被后面那个顶掉了。改成用 `rep_nxt` 取 `bidx + 1` 的字节，
   同时补上被 `default` 吃掉的 `S_EXEC` 分支。

### 全量回归

`sim/regress_adv11/summary.txt`：19 项全部 PASS，含 `tb_uart_ctrl`、本次新
加进来的 `tb_bmp_scale_chain`，以及 ADV10 的全部播放器 / 参数 / 音频用例
（缩放那条是全量回归里最慢的一项，840 s，因为它是逐个像素比对）。

两个和脚本有关的坑，都写在 `sim/run_regress_adv11.ps1` 的注释里：

- 串口模块用 `` `include `` 进 `hdmi_mm_player.v`，回归脚本里那三只文件要从
  独立编译列表里排除，否则 iverilog 会报重复定义；
- `tb_bmp_scale_chain` 反过来——它直接实例化 `bmp_scaler`，所以要自带
  `bmp_scaler.v` 与 `bmp_stream_parser.v`，走 `$special` 那条独立文件列表。

### 时序收敛

ADV11 加进来以后占用率冲到 97%，三个种子都收在临界点上：

| 种子 | 建立 WNS | 违例端点 | slice |
| --- | --- | --- | --- |
| 2 | -0.033 ns | 1 | 9522（97.16%） |
| 1 / 3 | -0.041 ns | 1 | 9464（96.57%） |
| 4 | -1.685 ns | 66 | 9495（96.89%） |

最差路径每条种子里都是同一处：`u_player/g_scale$u_scaler/v_nrm_reg` →
`mult2.b[9]`，也就是 `bmp_scaler.v` 里把余数换算成插值权重的那条除法网络。

根因是**位宽开大了**。`weight_h` / `weight_v` 的入口写的是 24 位，可余数
永远小于自己的分母（`H_DEN` 1280、`V_DEN` 960），12 位就装得下。多出来的
12 位虽然恒为 0，综合工具照样为它们建了逻辑。把两个入口收成 `input [11:0]`
之后：

| | 修复前（种子 2） | 修复后（种子 2） |
| --- | --- | --- |
| 建立 WNS / TNS | -0.033 ns / -0.033 ns | **+0.137 ns / 0** |
| 建立违例端点 | 1 | **0** |
| 保持 WNS / TNS | +0.021 ns / 0 | +0.030 ns / 0 |
| 保持违例端点 | 0 | **0** |
| slice | 9522（97.16%） | 9252（**94.41%**） |
| 线长 | 2 062 024 | 1 882 064 |

占位掉下来的两个多百分点比那 170 ps 更有价值：这是后面还能不能再往上加
功能的空间。

改的是"所有几何都要逐点对上"的那只缩放器，所以两边都验了：
`tb_bmp_scale_chain` 的四种几何（640×480 恒等、300×200 放大、960×720 缩小、
641×481 奇数行填充）在 `BRAM_PRIM=0`（推断行缓存）和 `BRAM_PRIM=1`（板级
BRAM 宏）两种实现下都是 `mismatch 0`，共 2 × 4 × 307 200 像素。这条用例也
已经加进 `sim/run_regress_adv11.ps1`。

产物：`hdmi_adv11_uart.bit`，另有备份
`backup/hdmi_adv11_uart_widthfix_seed2_20260929.bit`、
`_route_widthfix_seed2_20260929.qor`、
`_final_widthfix_seed2_20260929.timing` 与完整构建日志。

两份时序报告的读法：仓库根目录的 `final_timing.rpt` 是 TD 在 `route` 内部
打印的、`fix_hold` 之前的那一份（保持 -0.011 ns）；脚本自己在 `fix_hold` 和
`update_timing -mode final` 之后写的 `hdmi_adv11_uart_final.timing` 才是最终
结论，五个时钟域全部 0 违例。

## 7. 已知限制

- 槽位必须已经在帧缓存里（STATUS 的缓存位图）才能切；上电后六张图全部缓存
  完成大约需要几十秒，未缓存的槽位在界面上是灰的。
- 分辨率显示取自 PC 侧槽位文件。TF 卡里的图换过、PC 侧这份没换，界面上的数字
  就和板上实际播的那张不一致；反过来说，只要两边同源（都从 `sdcard/` 出），
  数字就是可信的。
- 串口不传图片。命令只能切到 TF 卡上已经缓存好的槽位，换图要替换 TF 卡里的
  `IMG0x.BMP` 后重新上电，片内目前没有图片写入通道。
- 字幕只支持 32 个字符且限定字形集，中文无法显示——这不是上位机的限制，
  而是片内字模 ROM 的大小取舍。
- 串口是持续占用式交互，演示时上位机窗口不要同时被别的串口工具打开。

### 板上 OSD 显示分辨率

电视画面左上角现在显示两行信息：

```text
ADV11 UART HOST
RES 640X480
```

第二行取自当前正在播放的 BMP 源文件尺寸，不是固定文本。`frame_store` 为每个
缓存槽保存宽高，切换画面时把对应尺寸锁存给 `ui_overlay`；宽高先在板上转成
BCD，再复用原有字模 ROM 渲染。这样没有复制第二套字体逻辑，也没有扩大字幕
缓冲区。示例：640×480 显示 `RES 640X480`，960×720 显示 `RES 960X720`。

第一版把根目录簇号换算压在单周期里，布线后建立时间差 0.502 ns。最终版仍按
50 MHz 约束，路由种子切到 1，并保留现有 UART、手动/自动切图、淡入淡出、
缩放和人声播报逻辑。通过版实测：

| 项目 | 结果 |
| --- | --- |
| 建立 WNS / TNS | +0.140 ns / 0 |
| 建立违例端点 | 0 |
| 保持 WNS / TNS | +0.021 ns / 0 |
| 保持违例端点 | 0 |
| slice | 9450（96.43%） |
